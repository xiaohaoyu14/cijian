# 3.0.1 语音无声与闪退修复

## 用户反馈

红米K80，每次点击喇叭无声，应用退出到系统桌面。安卓具体版本未知，用户不连接手机；本次没有设备崩溃堆栈，因此不能证明此缺陷是该设备闪退的唯一原因。

## 已复现的原生接口缺陷

原插件把Java lambda传给`generateWithCallback`。实际固定AAR的arm64 JNI包含方法描述符`([F)Ljava/lang/Integer;`，要求回调对象具有`invoke(float[]):Integer`。Java lambda只提供擦除后的`invoke(Object):Object`，没有该方法。`tests/native/PiperCallbackContract.java`以真实Kotlin Function1运行，复现对应NoSuchMethodException。上游JNI在GetMethodID失败后仍可能携带待处理异常继续执行JNI创建音频对象，ART可直接终止进程；外层Java try/catch不能兜住这种native abort。

源码依据（固定v1.13.3）：https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.3/sherpa-onnx/jni/offline-tts.cc 。实际AAR哈希仍由models.lock.json锁定。

## 改动

- 单词推理改成无回调的`engine.generate(text,0,1.0f)`。仍是实时Piper英文合成，不使用系统TTS或预打包逐词MP3。
- 推理在串行工作线程运行。取消不强行释放推理中的引擎；推理完成后丢弃已取消结果，避免播放旧词。
- 固定版Kotlin包装层允许构造结果ptr为0，sampleRate JNI会直接解引用。现在先检查该句柄，失败以普通错误返回，成功后才读采样率。
- 引擎资源用free()清空原生句柄，关闭后的任务提交受控拒绝。
- 增加AudioTrack初始化检查、播放超时及日志，不无限等待无进展音频设备；推理线程降为1。
- 包名/签名/数据库保持原值，版本3.0.1、versionCode6，完整版及4543词库均保留。
